# 开发文档

## 1. 技术栈

- 后端：Python 3.11、FastAPI、Pydantic、LangGraph、SQLite；
- 前端：React、TypeScript、Vite；
- 部署：Docker Compose、Nginx、Docker Desktop；
- 扩展：声明式 Skill、Python Plugin、受控 MCP；
- 质量：pytest、Ruff、mypy、Vitest、TypeScript、生产构建和浏览器验收。

## 2. 代码组织

后端业务代码位于 `src/yuwang`，API 装配位于 `apps/api`，前端位于 `apps/web`，本地评测任务位于 `evaluation_cases`，工具沙箱位于 `tool_sandbox`。新增工具应实现统一输入/输出模型和 `ToolSpec`，注册到 Registry，并补齐契约、越权、失败和脱敏测试。

## 3. 本地开发

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
cd apps/web
npm ci
cd ..\..
```

配置 `.env` 时只使用本机 Provider 和随机管理密钥；`.env`、`data/` 和日志不进入 Git。首次运行：

```powershell
.\yuwang.ps1 setup
.\yuwang.ps1 start
.\yuwang.ps1 doctor
```

## 4. 变更流程

1. 先阅读对应模块和测试，再修改最小范围代码；
2. 为公开行为补单元或 API 测试；
3. 工具变更补 Schema、权限、授权范围、错误码和输出脱敏检查；
4. 运行 `ruff check src tests`、`mypy` 和相关 pytest；
5. 提交前运行 `.\yuwang.ps1 check`、前端质量门禁和 Docker 验收；
6. 检查 `git diff --check` 与 `git status`，确认没有密钥、数据库和缓存。

## 5. Provider 与模型适配

Provider 通过统一结构化输出适配器接入。模型只负责公开计划、动作理由和结构化候选，服务端负责策略、执行、证据绑定和验证。真实 Provider 测试需配置隔离密钥，不能用测试替身结果冒充实测成绩。

## 6. 扩展边界

允许增加离线解析、授权本机探测和有界取证工具；不在本阶段引入任意 Shell、公网扫描、自动攻击或多租户。MCP 接入必须管理员显式白名单、声明权限和目标范围，并经过同一策略与审计链。
