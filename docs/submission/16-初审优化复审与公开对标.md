# 初审优化复审与公开对标

复审日期：2026-08-29。目标：在决赛测试平台尚未开放的前提下，提高 2026-09-05 初审材料的可信度、可复现性和五维评分覆盖。

## 一、结论

项目本体已经是可运行、可审计的安全 Agent 工程，不是简单的大模型 API 包装。真实优势包括 LangGraph 状态机、Run 不可变快照、统一工具契约、策略检查、检查点恢复、Evidence/TaskResult、独立 Local Judge、Docker 部署和完整质量门禁。

当前最大问题不是基础工程，而是提交证据不足：内置工具和真实案例范围较窄，黄金案例题面给出较多工具顺序提示，独立黄金 Compose 卷尚未完成真实 Provider 重复评测，脱敏轨迹未随提交包提供，技术报告和测试报告过薄，PPT 生成模板无法承载证据。

因此初审策略应从“继续堆平台功能”切换为“补真实能力证据、降低脚本化嫌疑、重建材料生成链”。

## 二、代码与工程复审

### 已经成立的能力

- `src/yuwang/agent/runner.py` 实现规划、动作选择、策略检查、工具执行、观察、重规划、验证、报告和恢复状态机。
- `src/yuwang/agent/components.py` 使用结构化 Planner 与 ActionSelector，不是固定步骤脚本。
- `src/yuwang/tooling/contracts.py`、`registry.py`、`executor.py` 统一工具 Schema、权限、风险、超时、幂等和审计。
- `src/yuwang/evaluation/local_judge.py` 与 `scorer.py` 从持久化事实独立评分，模型最终文本不能直接改变得分。
- Run 冻结 Task、Provider、Agent Profile、工具和授权快照；非幂等不确定调用不会自动重放。
- Compose 默认仅绑定回环地址，工具沙箱无 Shell、无命令参数、无外部网络，并配置只读文件系统、能力裁剪和资源限制。
- 2026-08-29 完整检查结果：后端 299 passed、9 skipped、覆盖率 86.69%；前端 100 passed；Playwright 4 passed；Ruff、mypy、生产构建、Compose 配置和 Windows 启动安全验收均通过。
- `npm audit --omit=dev --audit-level=high` 与完整 `npm audit --audit-level=high` 均为 0 vulnerabilities。

### 限制与可信度风险

- 内置工具只有 8 个，主要是文件、字符串、归档、编码、古典密码、Flag 格式和 localhost 只读 HTTP，无法支撑 Pwn、真实逆向、复杂 Web 利用等广泛主张。
- `tool_sandbox/app.py` 当前只有 `extract_strings`，Docker 隔离强，但功能覆盖弱。
- A/B/C 三个黄金案例可以证明闭环，不足以证明“通用”；普通 evaluation cases 大多是基础文本读取。
- `run_golden_demo.py` 在题面中直接给出工具名称、调用顺序和输出字段，适合回归验收，但不足以单独证明自主规划。
- C 修复后的两次结果是 8/9、9/9，不能只写成“修复后 9/9”。A 是 2/3，B 是 3/3，应报告原始成功次数和失败原因。
- 独立黄金 Compose 卷未配置真实 Provider，当前真实结果来自默认工作台，尚未完成干净环境复现。
- README 声称核心文件接近 400 行，但 `nodes.py` 和 `providers.py` 物理行数超过 900；末尾还残留训练分支说明，应清理不准确表述。

## 三、提交材料复审

### 阻断初审可信度的问题

1. 技术报告 PDF 只有 1 页，属于项目摘要，不足以解释五维评分、架构、决策、工具、评测和创新。
2. 测试报告只有 2 页，且仍写 298 passed，与当前 299 passed 不一致。
3. 证据矩阵引用“技术报告 2-4 页、测试报告第 4 页”，实际页码不存在。
4. PPT 的前 10 页基本只有标题和两行文字，真实轨迹、架构图、工具链、Judge、失败案例和统计图均未展示。
5. PPT 名称和页脚写“初审答辩”，但初审是线上材料评审，应改为“初审作品说明”。
6. 首页截图有大量同名“新任务”和 53 个任务，不像干净、可复现的评审环境。
7. 目前只有演示视频脚本，没有实际演示视频。
8. 脱敏 Run、trajectory、report、evaluation record 没有随提交证据目录提供。
9. 原创声明和部分手册仍是签字盖章占位稿。
10. 当前 `scripts/generate_presentation.ps1` 的单一模板决定了页面天然空泛，必须重建生成方式，不能只改 `$items` 文案。

## 五、初审前的实施优先级

### P0：必须完成

1. 在独立黄金 Compose 卷配置并测试现有真实 Provider，A/B/C 各运行至少 5 次。
2. 导出每次尝试的脱敏 evaluation record、trajectory、report 和失败分类，生成 SHA-256 清单。
3. 新增至少 6 个不泄露工具名和调用顺序的盲测案例；至少覆盖 Web、Crypto/编码、Forensics/附件、Reverse 静态、漏洞分析、应急响应。
4. 盲测集包含容易、一般、困难任务和至少 2 个预期可能失败的任务；禁止只保留成功样本。
5. 完成 dynamic、direct、禁用工具三组消融，固定 Provider、模型、预算和题集。
6. 重写 12-18 页技术报告、6-10 页测试报告、12-15 页证据型 PPT，并录制 6-8 分钟真实演示视频。
7. 修正全部数字、页码、文件名、版本、签字盖章和提交清单。

### P1：有时间再做

- 只在盲测暴露明确瓶颈时新增 1-2 个受控工具，优先静态文本/源码分析或沙箱内有界操作。
- 为评测结果生成 CSV/JSON 汇总和简单统计图。
- 增加一个真实 MCP 工具接入演示，证明统一契约而不是只展示配置页。

### 初审前不做

- 不引入多智能体、微服务、向量数据库或大规模 RAG 重构。
- 不开放任意 Shell、未授权公网扫描或自动攻击。
- 不为了数字好看删除失败结果、混合修复前后样本或使用测试替身冒充真实 Provider。
- 不把时间继续投入移动端装饰、设置页扩展或无证据的功能清单。

## 六、完成验收

只有同时满足以下条件，才可认为初审冲刺完成：

- 全新环境可按部署手册启动，完整质量门禁通过。
- 独立黄金卷 A/B/C 每个至少 5 个真实尝试，有原始成功数和失败分类。
- 至少 6 个无解法提示的盲测任务完成真实运行，成功和失败都可回放。
- 消融表使用相同模型和预算，统计口径可复算。
- 每个重要主张都能从证据矩阵跳转到真实文件、截图、Run 或代码位置。
- 技术报告、测试报告、PPT、视频和代码中的数字完全一致。
- 提交包不含 API Key、`.env`、数据库、未脱敏日志、隐藏 Flag 或 Judge 私有答案。
- 所有 PDF/PPT 页面完成逐页视觉检查，无空白页、裁切、重叠、过小截图或不存在的页码引用。
