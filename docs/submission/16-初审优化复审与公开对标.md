# 初审优化复审与公开对标

复审日期：2026-09-03。本文只说明作品本体的完成度、证据口径和适配边界，不替代组委会提交材料格式要求。

## 一、当前结论

项目已经从“大模型调用界面”发展为可运行、可恢复、可审计的安全 Agent 工作台。当前默认 Agent 为 `dynamic + verified`，能够先生成公开任务理解和计划，再调用受控工具，根据观察重规划，并在收尾阶段区分未验证、部分验证和独立验证通过。

## 二、已成立的能力

- LangGraph 状态机覆盖任务理解、计划、动作、策略检查、执行、观察、重规划、验证、报告和恢复；
- Run 冻结 TaskSpec、Provider、Profile、工具、授权范围、预算和附件摘要；
- ToolSpec/Registry/Executor/MCP 形成统一扩展边界；
- Artifact、ToolCall、ExecutionStep、EvidenceRecord 和 TaskResult 构成证据链；
- 本地 Judge 独立读取 SQLite 事实，模型最终文本不能直接改变评分；
- Docker Compose、Windows 脚本、健康检查、doctor、备份和恢复支持干净部署；
- 工具覆盖离线文件/归档、文本定位、IOC、时间线、编码、哈希、JWT、PCAP、静态分析和授权 localhost HTTP。

## 三、初审证据口径

当前可复核质量门禁：后端覆盖率 87.37%；前端 106 项测试通过；19 个工具契约通过；Docker 三服务健康；Windows doctor 15 项正常、0 警告、0 失败。真实 Provider 统计必须来自脱敏 Run、trajectory、report 和 evaluation record；测试替身和模型自述不计入真实成绩。

## 四、公开对标结论

NYU CTF Bench、BoxPwnr、HackSynth、CyberGym-E2E 等公开工作在大规模题库、平台接入或端到端利用方面具有不同侧重。本项目不复制其代码、不声称同口径领先，也不把公开项目的题量或成绩移植到自身。可借鉴的共同做法是：任务与评测分离、轨迹可回放、验证器独立、失败样本保留和部署环境可复现。

## 五、明确限制

当前版本不支持任意 Shell、未授权公网扫描、自动攻击、多智能体协作、外部 CTFd 提交、主办方平台判分或指定网关。PCAP/JWT 仅做离线静态分析；MCP 需要管理员白名单和同一策略链。

## 六、封版原则

提交前只做会提高可复现性和事实一致性的修改：更新报告数字、补充脱敏运行证据、清理缓存和敏感数据、重新生成 PDF/PPT、完成干净克隆验收。不要为初审临时扩大安全边界或堆叠未验证功能。
