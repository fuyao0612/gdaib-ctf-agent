# 上下文、记忆与完成可信等级

## 上下文构建

Agent 的 `ContextBuilder` 从不可变 TaskSpec、任务历史、用户补充、记忆、附件、工具 Schema、当前计划、观察和剩余预算构建请求。安全层与平台层始终置于用户模板之前；任务历史、附件、网页、补充和工具输出全部标记为不可信数据。

默认上下文窗口为 262144 Token，可设为 32K、64K、128K、256K 或合法自定义值。实际窗口取用户设置与 Provider 声明模型窗口的较小值，并预留至少 8192 Token（或窗口的 10%）给输出。默认估算器对 CJK/全角字符按接近一 Token 估算，避免 `len(text)//4` 低估中文。

压缩按 Token 占用比例触发：达到输入预算 75% 时生成或更新增量确定性摘要，90% 时执行强制降级。摘要仅记录公开事实，结构包含目标与约束、已完成操作、失败尝试、重要发现、待办事项和证据引用；系统规则、当前任务、最新纠偏、授权范围、未完成工具调用和最近消息始终保留。工具长输出和大附件仅保留摘要、Artifact 引用、路径及必要首尾片段。语义摘要不可用或仍超预算时使用确定性安全裁剪，原始 SQLite 消息、事件和 Artifact 永不删除。每次新摘要版本写入 `context_compacted`，记录压缩前后 Token、原因、版本和耗时；摘要摘要指纹随检查点恢复，暂停、刷新或重启不会重复压缩。

`.txt`、`.md`、`.json` 和 `.log` 可作为受限核心上下文读取：只允许受控相对路径，限制读取字节、UTF-8 解码、行数和字符数。二进制附件只进入元数据。附件文本不能修改系统规则，也不是可执行代码或安全工具。

## 线程记忆

记忆按 Thread 持久化，类型包括线程摘要、运行摘要、重要事实和用户补充。AgentProfile 可禁用记忆及限制事实数量；API 支持查看、整体禁用/启用和清除。运行完成会保存简短运行摘要，人工补充会保存为用户输入记忆。记忆进入模型前仍按不可信内容处理。

失败运行还会保存经脱敏的 `run_summary`，其中只包含公开失败路径和下一步建议。后续 Run 仅在启用记忆和运行摘要上下文时，才会在 `previous_failed_paths` 收到这些历史事实；规划与动作选择提示要求在没有新证据时避免原样重复失败工具路径。关闭记忆时该字段严格为空，不会改变授权、工具或系统策略。测试覆盖了该开启/关闭消融差异。

## 完成模式

- `advisory`：用于总结、解释和规划等纯模型任务。允许无工具结束，但 Run、界面和报告必须显示“模型生成，未经外部验证”，证据等级为 `model`。
- `structured`：模型返回对象后必须通过 AgentProfile 配置的 JSON Schema，证据等级为 `structured`。Schema 不通过时不能完成。
- `evidence`：继续要求候选绑定成功工具调用或其他外部证据，并通过确定性规则，证据等级为 `external`。

Run 分开保存生命周期状态、`validation_status` 和 `evidence_level`。内部“已完成”不等于“外部已验证”。

## 人工补充与恢复

普通模式的 `request_input` 可按配置进入 `waiting_input`，保存完整检查点并释放当前执行。用户通过补充接口提交内容后，系统把它作为不可信上下文和记忆，从 `input_received` 检查点继续。竞赛模式只能按配置自主重规划或明确失败，不会伪装等待。

停止会取消正在进行的模型协程。恢复和重试沿用检查点中的步骤、请求、Token、费用和累计时间，不重置已消耗预算；不确定的非幂等工具调用仍禁止自动重放。
